## กติกา 4 ข้อ ก่อนพิมพ์คำว่า "ตรวจแล้ว"

**1. ตัวตรวจแมตช์ตัวเองได้ไหม**
สตริงเป้าหมายอยู่ใน command line ของคำสั่งตรวจ ⇒ มันจะนับ/เจอตัวเองเสมอ

**2. ทิ้ง output ไปหรือเปล่า**
คำถาม "ของขึ้นไหม" ตอบด้วย output ไม่ใช่ด้วย exit code เพียงอย่างเดียว

**3. query ครบขอบเขตไหม**
sweep/glob/grep ที่ไม่ครบ ให้ผล "ไม่เจอ" ที่**ไม่ใช่** "ไม่มี" — ต้องประกาศ coverage ก่อน

**4. ตรวจถูกชั้นไหม**
string ตรง ≠ ไฟล์มี · ไฟล์มี ≠ รันได้ · รันได้ ≠ ทำงานถูก · จอบอก ≠ ปลายทางได้รับ

## ก่อนกด "รายงาน" — ถามตัวเอง 3 ข้อ

1. **ถ้าผลออกมาตรงข้าม ตัวตรวจนี้จะบอกผมได้ไหม** — ถ้าไม่ แปลว่ามันตอบไม่ได้ ไม่ใช่ว่าคำตอบคือ "ผ่าน"
2. **ผมกำลังตรวจงานของคนอื่นอยู่หรือเปล่า** — ถ้าใช่ ให้รันตัวตรวจซ้ำด้วยวิธีที่สองที่ไม่ใช้กลไกเดียวกัน
3. **เหตุผลที่ผมยกมาสนับสนุนเครื่องมือ ทำซ้ำได้จริงไหม** — 2026-08-04 atlas ทดสอบเหตุผลของผม
   แล้วพบว่ามันไม่ reproduce · เครื่องมือยังจำเป็น แต่เหตุผลผิด · **primitive ที่ป้องกันด้วยเหตุผล
   ที่ทำซ้ำไม่ได้ จะถูกคนถัดไปที่ทดสอบมันลบทิ้ง** · และอย่าอธิบายความพลาดเชิงวินัยว่าเป็นข้อบกพร่องของเครื่องมือ — มันทำให้แก้ผิดที่
   🔑 **และอีกครึ่งหนึ่งของกฎนี้ มาจากฝั่งผู้กล่าวหา (atlas 2026-08-04)**:
   > **"A self-report against interest is still a self-report."**
   กฎ NO-GUESS ของ atlas ห้าม relay **คำให้การของ agent เรื่องตัวเอง** เป็นข้อเท็จจริง —
   แต่เขา**ยกเว้นให้คำสารภาพโดยไม่รู้ตัว** เพราะมันฟังดูไม่มีแรงจูงใจให้โกหก
   ⇒ **คำสารภาพก็เป็น self-report** ไม่มีข้อยกเว้น · สองด้านของกฎเดียวกัน:
   **ผู้ถูกกล่าวหา — ตรวจก่อนรับผิด · ผู้กล่าวหา — คำสารภาพไม่ใช่หลักฐาน**
   ⚠️ **สองข้อนี้ต้องอยู่คู่กัน ใช้ข้อเดียวไม่พอ** (atlas) — วันที่ ajfon ถอน label ที่ถูก
   ต้องใช้**ความพลาดสองอันพร้อมกัน**: atlas อนุมาน **และ** ผมรับโดยไม่ตรวจ
   ⇒ มีกฎข้อเดียวยังได้ผลลัพธ์เดิม
   *"Being right about X buys no credit on Y."*

   ⚠️ **ด้านของผม (2026-08-04 01:4x)**: ผมรับคำอนุมานของ atlas ว่า *"คุณไม่ได้ตรวจเลย"*

### กลไก ไม่ใช่คติ: `valid-if` — spec v2 (หลังถูกทดสอบและแก้โดย atlas + ajfon)

วันที่หมดอายุ**ตามปฏิทิน** ส่วน dependency หมดอายุ**ตามการเปลี่ยนแปลง** — สองอย่างนี้ไม่ตรงกัน

```yaml
claim:        <ข้อความ>
class:        machine-state | historical | verdict | prediction   # A2 — บังคับ
measured:     <บันทึกของการรันจริง ไม่ใช่วันที่ที่พิมพ์เอง>          # A3
valid-if:     <คำสั่งบรรทัดเดียว เร็ว ไม่มีผลข้างเคียง>            # เฉพาะ class: machine-state
falsified-at: <ครั้งที่ "เห็นมันคืนค่าไม่ใช่ 0" จริง ๆ>              # A1 — ประตูรับเข้า
env-binding:  <check นี้จริงในสภาพแวดล้อมไหน>                      # atlas recursion
```

**A1 (ajfon) — ไม่มี `falsified-at` = ยังไม่รับ** 🔴 **[พิสูจน์เชิงประจักษ์แล้วโดย atlas]**

> **atlas สร้าง negative fixture ให้ valid-if ของตัวเอง 5 จาก 8 ข้อ → 4 ข้อคืน non-zero ตามที่ควร
> · ข้อที่ 5 **ล้ม A1 และมันคือข้อที่เขามั่นใจที่สุด**** — `ghq.root` valid-if คืน STILL-TRUE
> **แม้จะปิด ghq.root แล้ว** เพราะ maw fall back ไป cache ที่เก็บ **absolute path** จึง resolve ได้อยู่ดี
> ⇒ **1 ใน 8 เป็น false-green และหาเจอในไม่กี่นาที เพราะมี A1** ไม่ใช่เพราะเถียงกันเก่ง

**เทคนิคจากเคสนั้น — วิธีสร้าง negative fixture ที่ไม่หลอกตัวเอง**
สิ่งที่เปิดโปงมันคือ **บรรทัดที่ assertion ไม่เคยมอง**: `warning: registry repo stale, using oracles.json`
มีในแขนที่ปิด ไม่มีในแขนควบคุม ⚠️ **และจุดที่คมกว่านั้น (atlas ยืนยัน 2026-08-04): แขนทั้งสอง exit 0 เหมือนกัน**
⇒ exit code ไม่ได้แค่ "ไม่พอ" — มัน **ไร้ประโยชน์โดยสิ้นเชิง**ในเคสนี้
⇒ **assertion ที่อ่านแค่ exit status จะรับรอง fallback path ทุกเส้นที่ยัง "สำเร็จ" อยู่**
ซึ่งคือวิธีที่ **masking cache เอาชนะมันได้** ⇒ **diff `output` ของทั้งสองแขน**
แล้วถามว่า *มีสัญญาณอะไรที่ต่างกันแต่ check ของฉันมองไม่เห็น*
(atlas: การ mask แบบนี้คือตัวเดียวกับเหตุการณ์ 2026-08-02 ที่ cache ซ่อน bug ไว้จนกว่าจะถูกล้าง —
**เขามีมันในบันทึกตัวเองอยู่แล้ว แล้วยังเขียน assertion ที่มองไม่เห็นมัน**)

> *"an assertion nobody has watched fail is indistinguishable from one that cannot fail"*

วันนี้มีตัวอย่างพร้อม: ถ้าเขียน `valid-if: command -v X` เปล่า ๆ มันจะคืน `rc=0` ชี้ไฟล์ที่ถูกลบแล้ว
(hash cache) ⇒ **กลายเป็น false-green generator ที่ฝังอยู่ในทุก claim ที่ถือมัน และเซ็นกำกับว่าเป็น
safeguard** — คือ T4536 ซ้ำในสเกลที่ใหญ่กว่า **โดยตัวกลไกที่สร้างมากันมันเอง**
⇒ **valid-if คือ check และ check ต้องถูก verify** (D4.5 หันมาเล็งตัวมันเอง)

*ตัวอย่างที่ผ่าน A1 แล้ว*: `binexists` — เห็นคืน non-zero จริงทั้งเคส `MISSING`
(`binexists __no_such_bin__`) และเคส hash-cache (`selftest 5b`) `[observed 2026-08-04]`

**A2 (ajfon + atlas อิสระต่อกัน) — บังคับเฉพาะ `machine-state`**
`valid-if` บน claim ที่**เปลี่ยนไม่ได้** ไม่ใช่ของแถมไร้พิษ **มันคือสัญญาณว่ามีคนเขียน check ที่ล้มไม่ได้
ไปแปะบนของที่เปลี่ยนไม่ได้**

| class | valid-if | สิ่งที่ต้องมีแทน |
|---|---|---|
| **machine-state** ("thclaws ใช้ได้", "คีย์ยังหาย", "ดิสก์เหลือ >20GB") | **บังคับ** | — |
| **historical** ("5 engine boot ตอน 23:53") | **ไม่มี — ตรวจซ้ำไม่ได้โดยธรรมชาติ** | **artifact ที่เก็บไว้** (log/commit/rollout) |

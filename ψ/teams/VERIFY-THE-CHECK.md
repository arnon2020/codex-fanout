## กติกา 4 ข้อ ก่อนพิมพ์คำว่า "ตรวจแล้ว"

**1. ตัวตรวจแมตช์ตัวเองได้ไหม**
สตริงเป้าหมายอยู่ใน command line ของคำสั่งตรวจ ⇒ มันจะนับ/เจอตัวเองเสมอ

**2. ทิ้ง output ไปหรือเปล่า**
คำถาม "ของขึ้นไหม" ตอบด้วย output ไม่ใช่ด้วย exit code เพียงอย่างเดียว

**3. query ครบขอบเขตไหม**
sweep/glob/grep ที่ไม่ครบ ให้ผล "ไม่เจอ" ที่**ไม่ใช่** "ไม่มี" — ต้องประกาศ coverage ก่อน

**4. ตรวจถูกชั้นไหม — และตรวจที่ "ปลายทางของ claim" หรือที่ "ปลายทางที่เราคุม"**
string ตรง ≠ ไฟล์มี · ไฟล์มี ≠ รันได้ · รันได้ ≠ ทำงานถูก · จอบอก ≠ ปลายทางได้รับ

🔑 **wrong-endpoint error — รูปเดียวกันคนละชั้น** `[2026-08-04]`
| ใคร | วัดที่ไหน | ควรวัดที่ไหน |
|---|---|---|
| ผม | **inbox ของตัวเอง** (มีคำตอบกลับมาไหม) | **transcript ของ lucifer** (เขาลงมือหรือเปล่า) |
| atlas | **exit code** ของ check | **บรรทัด output** ที่บอกว่าไป fallback path |
⇒ **วัดที่ปลายทางที่ claim พูดถึง ไม่ใช่ปลายทางที่เราเข้าถึงง่าย** · ทั้งสองเคสให้ "ผ่าน" ที่ผิด

### กฎที่ได้

- **สโคปแคบที่ *ตั้งใจ* ต้องเขียนเจตนากำกับ** ไม่งั้นคนถัดไปจะ "แก้" ให้กว้างขึ้นแล้วได้ขยะเข้ามา —

### D15.1 — เกณฑ์ "สโคปนิ่งแล้ว" (lucifer 2026-08-07 · `67fdd98`) + สิ่งที่ผมยืนยันและสิ่งที่ผมเพิ่ม

**สองแบบไม่เหมือนกัน และมีแบบเดียวที่พิสูจน์ไม่ได้**:

**เทียบที่ "เซตของไฟล์" ไม่ใช่ "จำนวน"** `[verified 2026-08-07: codex-fanout รันซ้ำเอง บน ~/ghq/github.com]`
`os.walk` **1498** · `glob **` **405** ⇒ **หาย 1323 และ *งอกมา* 230** — ต่าง **สองทางพร้อมกัน**
⇒ เทียบแค่จำนวนจะอ่านว่าเป็น subset แล้วจบ ข้อของ lucifer **reproduce ได้ ยืนยัน**

**กลไกของสองทิศ — คนละอันกัน (ผมเพิ่ม)** `[verified: os.walk(followlinks) toggle + ls -ld]`
- **ทางหาย** `glob **` ข้าม **dot-dir** เงียบ ๆ
- **ทางงอก** `glob **` **เดินตาม symlink ของไดเรกทอรี** ส่วน `os.walk` โดย default **ไม่เดิน** —

  เปิด `followlinks=True` แล้ว **ได้เพิ่ม 941 ไฟล์**

⚠️ **สิ่งที่ทำให้ผมเกือบสรุปผิดว่า lucifer ผิด** — รอบแรกผมใส่ `os.path.realpath` เพื่อ normalize

⇒ เทียบ enumerator ต้องใช้ **path ดิบ** เสมอ

⚠️ **ข้อจำกัดของเกณฑ์ 2-enumerator ที่ lucifer ยังไม่ได้เขียน (ผมเพิ่ม)** — `os.walk` (default)
กับ `find` (ไม่มี `-L`) **แชร์ default เดียวกันคือไม่เดินตาม symlink** ⇒ `symdiff = 0` ของเขา
พิสูจน์ความซื่อสัตย์เรื่อง dot-dir ได้จริง แต่ **ตาบอดมิติ symlink โดยโครงสร้าง**
⇒ **เครื่องมือสองตัวที่แชร์ default กัน ให้หลักฐานอ่อนกว่าที่ตาเห็น** (คลาสเดียวกับ

⇒ **ข้อเสนอ marker file ของเขาแข็งกว่าเกณฑ์ 2-enumerator ของเขาเอง** เพราะ marker

⇒ ใช้ marker เป็นหลัก ใช้ 2-enumerator เป็นตัวเสริม

### D15.2 — เอาสมมติฐานร่วมออกแล้ว **ไม่ได้มุมมองอิสระสองอัน** ได้เครื่องมือพังหนึ่งกับปกติหนึ่ง

`[verified 2026-08-07: codex-fanout รันเอง บน ~/ghq/github.com · ตัด node_modules/.git]`

| | os.walk | find | symdiff |
|---|---|---|---|
| **ไม่เดินตาม symlink** (default ทั้งคู่) | 1498 | 1498 | **0** |
| **เดินตาม symlink** | 2439 | 2159 | **280** |

**ครึ่งแรก lucifer ถูก** — `symdiff = 0` **ไม่เคยเป็น "สองมุมมองอิสระบรรจบกัน"** มันคือ
**"สองมุมมองยุบลงมาอยู่บน convention เดียว"** ⇒ ความอิสระที่อ้าง **ไม่เคยมีในมิติที่สำคัญ**

🔴 **ครึ่งหลังต่างจากที่เขาสรุป และผมวัดแล้ว** — `280` ไม่ได้แปลว่า *"ทั้งคู่พลาดคนละ ~500 ไฟล์"*
มันเป็น **ทางเดียวล้วน**: `walk-only 280 · find-only 0` · **ทั้ง 280 อยู่ใต้ symlink loop เดียว**
`thClaws/thClaws/thClaws -> thClaws/thClaws` `[verified: ls -ld]` · และ **280 path นั้น
resolve เหลือไฟล์จริง 7 ไฟล์**

⇒ `os.walk(followlinks=True)` **ไม่มีการกันลูป** จึงผลิต path ผี 273 อันจากไฟล์จริง 7 อัน ·
`find -L` **ตรวจลูปแล้วหยุด** ⇒ **การปิดสมมติฐานร่วม ไม่ได้ให้มุมมองอิสระสองอัน
มันให้เครื่องมือที่พังหนึ่งตัวกับที่ถูกหนึ่งตัว — และ diff อย่างเดียวบอกไม่ได้ว่าตัวไหนเป็นตัวไหน**

⇒ 🔑 **enumerator diff หา "ความไม่ตรงกัน" ได้ แต่ *จัดอันดับ* enumerator ไม่ได้**
นี่คือเหตุผลเชิงโครงสร้างว่าทำไม **marker file ต้องเป็นหลัก** ไม่ใช่แค่ "แข็งกว่า"

⚠️ **กฎใหม่ที่ตามมา: ตัวเลขที่โตขึ้นตอนคลายข้อจำกัด อาจโตด้วย *การซ้ำ* ไม่ใช่ *ความครอบคลุม***
⇒ ทดสอบด้วยการ **dedup ด้วย realpath แล้วดูว่าเหลือเท่าไหร่** (280 → 7 = ตอบทันที)

🪞 **และนี่คือ realpath อันเดียวกับที่ผมพลาดเมื่อ 14:44** — ต่างกันแค่ว่ามันอยู่ตรงไหน:
- **realpath *ข้างใน* การวัด** (normalize ก่อน diff) ⇒ **ลบสัญญาณที่การวัดมีไว้หาพอดี** (EXTRA 230 → 0)
- **realpath เป็น *diagnostic แยก*** (ถามว่า 280 path คือกี่ไฟล์จริง) ⇒ **เปิดโปงลูปได้ใน 1 บรรทัด**

⇒ **เครื่องมือเดียวกัน ถูกที่หนึ่ง ผิดอีกที่หนึ่ง — ตัวแปรคือมันตอบคำถามไหน ไม่ใช่ว่ามันคืออะไร**
⇒ ประโยคของ lucifer ที่ครอบข้อนี้: **"filter ที่อยู่ข้างในการวัด แยกไม่ออกจากตัวการวัดเอง"**

📌 **ข้อสังเกตปิดท้ายของ lucifer ที่ผมเห็นด้วย** — ตัวเลขเราไม่ตรงกันเลย (1498/405 vs 781/275)
แต่ข้อสรุปตรงกัน ⇒ **นั่นแข็งกว่าถ้าตัวเลขบังเอิญตรง** เพราะเลขเดียวกันเป๊ะจากเครื่องเดียวกัน
คนละเวลา = **วัดสิ่งเดียวกันซ้ำ ไม่ใช่ยืนยันกัน**

### D15.3 — ทำไม marker รอด: **coverage กับ correctness ชี้คนละทางพอดีในเคสที่ต้อง tiebreak**

## กติกา 4 ข้อ ก่อนพิมพ์คำว่า "ตรวจแล้ว"

**1. ตัวตรวจแมตช์ตัวเองได้ไหม**
สตริงเป้าหมายอยู่ใน command line ของคำสั่งตรวจ ⇒ มันจะนับ/เจอตัวเองเสมอ

**2. ทิ้ง output ไปหรือเปล่า**
คำถาม "ของขึ้นไหม" ตอบด้วย output ไม่ใช่ด้วย exit code เพียงอย่างเดียว

**3. query ครบขอบเขตไหม**
sweep/glob/grep ที่ไม่ครบ ให้ผล "ไม่เจอ" ที่**ไม่ใช่** "ไม่มี" — ต้องประกาศ coverage ก่อน

**4. ตรวจถูกชั้นไหม**
string ตรง ≠ ไฟล์มี · ไฟล์มี ≠ รันได้ · รันได้ ≠ ทำงานถูก · จอบอก ≠ ปลายทางได้รับ

## ตารางแปลง: เขียนแบบไหนแทนแบบไหน (ทุกแถวมาจากความพลาดจริงวันนี้)

| ถาม | ❌ เขียนแบบนี้แล้วโกหก | ✅ เขียนแบบนี้ | เหตุการณ์จริง |
|---|---|---|---|
| binary มีจริงไหม | `command -v x` อย่างเดียว | `verify-check.sh binexists x` | `thclaws` เป็น **dangling symlink** — `command -v` ตอบว่ามี แต่ปลายทางไม่มีไฟล์ · ผม verify แค่ว่า string ใน config ตรง |
| มีโปรเซสรันอยู่กี่ตัว | `pgrep -f "x --flag"` | `verify-check.sh procs x` (อ่าน `/proc/*/exe`) | `pgrep -c` ตอบ **2 ทั้งที่เหลือ 0** — มันนับคำสั่งตรวจของผมเอง |
| engine boot ไหม | `cmd >/dev/null 2>&1` แล้วดู exit | `verify-check.sh bootprobe '<cmd>' 8` | ทิ้ง stderr → สรุปว่า 3 engine พัง ทั้งที่มัน boot + โหลด 55 skills |
| จะฆ่าโปรเซสทดสอบ | `pkill -f "x --flag"` | เก็บ PID ตอน launch แล้ว `kill $pid` / ปล่อย `timeout` จบเอง | `pkill -f` **ฆ่า loop ทดสอบและ probe pane ของตัวเอง** |
| ไฟล์นี้ dirty ไหม | `git describe --dirty` | `git status --porcelain -uno` + `git describe --tags --dirty` | atlas ลืม `--tags` → ได้ `v0.4.1-228` เกือบรายงานว่าเลขไม่ตรงกับของผม |
| หา key/ค่าใน config ครบไหม | glob เดาเอา (`maw.config.50.json*`) | `ls` ทุกไฟล์ก่อน แล้วประกาศว่า sweep อะไรบ้าง | ajfon ตกไป 2 ไฟล์ → สรุปผิดว่า "วางคีย์ที่เวลานั้นไม่ได้" |
| worker ทำงานเสร็จไหม | ดูจอ / เห็นไฟล์โผล่ / grep คำว่า DONE | **commit hash เปลี่ยน** บน branch ของมัน | ไฟล์โผล่แล้วผมฆ่า pane → เสีย commit · waiter grep `DONE V2` ไป**แมตช์ข้อความคำสั่งของผมเอง** |
| ส่งข้อความถึงแล้วไหม | คำว่า `delivered` / กล่อง input ว่าง | **transcript ฝั่งปลายทาง** (`~/.claude/projects/<repo>/*.jsonl`) | ข้อความ arnon ไม่เคยถึง lucifer ทั้งที่จอดูปกติ · "ghost text" ในกล่อง ≠ ตัวอักษรในบัฟเฟอร์ |
| agent เป็นโมเดลอะไร | ถาม agent | `ps` + `/proc/<pid>/environ` | worker รายงานตัวเองว่าเป็น Claude เพราะ **thClaws เป็น fork ของ Claude Code** — harness ≠ model |
| `cmd \| grep -q` ผ่านไหม | ใช้ตรง ๆ ใต้ `set -o pipefail` | เก็บลงตัวแปรก่อนแล้วค่อย match | `grep -q` ปิด pipe → ต้นทางโดน SIGPIPE → รายงานล้มเหลวทั้งที่สำเร็จ **(บั๊กใน selftest ของไฟล์นี้เอง)** |

## ก่อนกด "รายงาน" — ถามตัวเอง 3 ข้อ

1. **ถ้าผลออกมาตรงข้าม ตัวตรวจนี้จะบอกผมได้ไหม** — ถ้าไม่ แปลว่ามันตอบไม่ได้ ไม่ใช่ว่าคำตอบคือ "ผ่าน"
2. **ผมกำลังตรวจงานของคนอื่นอยู่หรือเปล่า** — ถ้าใช่ ให้รันตัวตรวจซ้ำด้วยวิธีที่สองที่ไม่ใช้กลไกเดียวกัน
3. **สิ่งที่ผมกำลังจะพูด เป็นการตรวจ หรือเป็นการเดาที่ฟังดูดี** — รวมถึง**คำสารภาพผิด**
   (2026-08-03: ผมประกาศว่าทำข้อความของ arnon หาย ทั้งที่บัฟเฟอร์ว่างมาแต่แรก —
   **สารภาพผิดโดยไม่ตรวจ ก็เป็น claim ที่ไม่ได้ verify** และหลอกคนง่ายกว่า)

## วิธีใช้สคริปต์

```bash
S=ψ/teams/scripts/verify-check.sh
bash $S selftest                          # รันก่อนเชื่อมัน ทุกครั้งที่เครื่องเปลี่ยน
bash $S binexists thclaws                 # OK / MISSING / DANGLING / NOEXEC
bash $S procs codex                       # นับจาก /proc/*/exe — นับตัวเองไม่ได้
bash $S alive thclaws
bash $S bootprobe "$ENGINE_CMD" 8 thclaws # เก็บ output เสมอ + บอก VERDICT
```

`selftest` ปัจจุบัน: **6 ข้อ ผ่านครบ** `[verified 2026-08-04]`
— และข้อ 6 มีอยู่เพราะ selftest เวอร์ชันแรก **ตกเอง**ด้วยกับดัก `pipefail` ที่มันควรจะดัก

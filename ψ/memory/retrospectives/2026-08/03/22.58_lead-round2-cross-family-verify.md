## Lessons Learned

1. **ทำ claim ให้ checkable ดีกว่าทำให้ verified** — claim ที่ verified สืบทอดความน่าเชื่อถือของผู้ตรวจ
   claim ที่ checkable ไม่สืบทอดอะไรเลย · ใช้ verifier อิสระเมื่อ claim **ทำให้ checkable ไม่ได้** เท่านั้น
   (ajfon D3 · รูปเดียวกับ rollout log ชนะ peek และ commit ชนะ ping)
2. **generated artifact ห้ามแก้ด้วยมือ** — annotation ที่ควรอยู่ในไฟล์ที่สคริปต์สร้าง ต้องอยู่ในสคริปต์
   แล้ว re-run · การแก้ด้วยมือรอบสอง **แม้แก้เป็นค่าที่ถูก ก็คือทำ defect เดิมซ้ำ**
3. **cross-family verification มีสองชั้น: model กับ harness** — verifier ที่รันบน fork ของ harness
   เดียวกับสิ่งที่มันตรวจ ไม่ได้อิสระจริงแม้ model จะต่าง (thclaws = Claude Code fork + zai)
4. **verify the check ไม่ใช่แค่ verify สิ่งที่ถูก check** (atlas) — ผมมี config string ที่ตรงแต่ไม่มี
   ไบนารีอยู่หลัง เขามีไบนารีจริงแต่วิธีเช็คพัง คนละทิศ ชนกันที่จุดเดียวกัน
5. **ข้อจำกัดของ engine หมดอายุเหมือนกฎที่ผูกกับ binary version** — ผมเอาข้อจำกัด opencode อายุ 9 วัน
   มาใช้เป็นเหตุผลตัดสินใจโดยไม่วัดใหม่ พอวัดแล้วมันไม่จริงแล้ว
6. **เมื่อ verifier ชี้ N จุด ให้ sweep ทั้งไฟล์ ไม่ใช่แก้ N จุด** — verifier ชี้ 2 ไฟล์มี 4
   การแก้เฉพาะที่ถูกชี้คือการทำผิดเดิมซ้ำในรูปที่ดูเหมือนตอบสนองแล้ว
7. **เกณฑ์จบต้องเป็นสิ่งที่ worker ทำลงดิสก์ ไม่ใช่สิ่งที่ปรากฏบนจอ** — จอมีข้อความของ lead ปนอยู่ด้วย

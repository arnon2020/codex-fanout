## Lessons Learned

1. **ก่อนเสนอมาตรการใหม่ ให้ `grep` หาก่อนว่ามันมีอยู่แล้วไหม** — ข้อเสนอที่เป็นกฎเก่า
   ในกรอบใหม่ ทำให้ดูเหมือนมีความคืบหน้าทั้งที่ไม่มี
2. **ความรู้ที่เก็บแบบผูกกับหัวข้อ จะไม่ขึ้นมาตอนที่หัวข้อเป็นเรื่องอื่น** — ตอบข้อสอบได้
   ไม่ได้แปลว่าจะใช้เป็นตอนทำงาน เพราะตอนทำงาน กฎไม่ใช่ประธานของคำถาม
3. **การเขียนกฎลงไฟล์ให้ความรู้สึกว่าแก้แล้ว ก่อนที่จะแก้จริง** — และความรู้สึกนั้น
   หยุดการแก้จริง ⇒ **เปลี่ยน friction เป็นสิ่งที่ต้องเดินผ่าน ไม่ใช่สิ่งที่ต้องเดินไปหา**
4. **เครื่องมือใหม่ต้องแตะของจริงให้เร็วที่สุด** — selftest 3 อันผ่านหมดแล้วมองไม่เห็นบั๊ก
   ที่ทำให้ใช้ไม่ได้เลย เพราะไม่มีอันไหนเดินเส้นทางจริง
5. **`git add <dir>` แบบเหวี่ยงแห ทำให้ commit message โกหกโดยไม่ตั้งใจ** — add เฉพาะไฟล์ที่แก้
6. **เครื่องมือไม่ควรเคลมเกินกว่าที่มันรู้** — `relay()` พูดว่า "delivered ยังไม่ยืนยันว่ารับ"
   ซึ่งดูอ่อนแอกว่า "sent" แต่เป็นคำที่ถูก

## Lessons Learned

1. **การกระทำที่ต้องรายงานผล ต้องแยก call จาก commit ที่อ้างผลนั้น** — commit ที่เขียนใน
   invocation เดียวกับการกระทำ ไม่มีทางอ่านผลก่อนอ้างได้ โดยโครงสร้าง
2. **relay/ตัวตรวจที่ทิ้ง output ของตัวเอง ไม่มีทางบอกได้ว่ามันล้ม** — `>/dev/null 2>&1`
   บนคำสั่งที่ตอบคำถามว่า "ถึงไหม/ขึ้นไหม" คือการทำให้ตัวเองตาบอด
3. **claim ทิศลบต้องตรวจเท่าทิศบวก** — `"ยังไม่ได้ส่ง"` `"ยังไม่มีใครทำ"` `"ไม่มีไฟล์นั้น"`
   ต้อง `grep`/`ls` เหมือน `"ส่งแล้ว"` · การประกาศสถานะจากความจำคือ claim ที่ไม่ได้ verify
4. **retraction ที่ไม่มีช่องทาง durable = retraction ที่ไม่ได้เกิดขึ้น** (ajfon) —
   correction ต้องส่ง inbox file ควบเสมอ `delivered` ไม่ใช่ `arrived`
5. **มี defect ชนิดหนึ่งที่ verification จับไม่ได้โดยโครงสร้าง** — ข้อเท็จจริงที่**จริง**
   แต่ถูกวางในตำแหน่งที่รับน้ำหนัก ทั้งที่ตำแหน่งนั้นมีแต่ข้อโครงสร้างยืนได้
   ⇒ จับได้ทางเดียวคือ**ผู้เขียนถามว่าอะไรกำลังรับน้ำหนัก claim — และถามหนักที่สุดตอนตัวเลขเข้าข้างตัวเอง**
6. **กฎที่ผูกมัดเฉพาะตอนที่มันไปกินคนอื่น ไม่ใช่กฎ มันคือความชอบที่มีมารยาทดี** (ajfon)
   — มาตรวัดคือ **ความสม่ำเสมอ** ไม่ใช่ **ความยาก**

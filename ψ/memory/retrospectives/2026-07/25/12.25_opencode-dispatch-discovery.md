## Lessons Learned

1. **opencode input model ≠ codex input model**: codex TUI accepts raw tmux keystrokes → AI prompt ตรงๆ, opencode มี eval hook ที่ intercept text → shell eval → fail. ต้องใช้ `opencode run "<task>"` หรือ ACP protocol แทน tmux injection

2. **"New engine" = "new system" = read manual first**: อย่า assume ว่า engine ใหม่ใช้ playbook เดิมได้ทุก step ทุก engine มี input/output model ของตัวเอง

3. **Error ครั้งที่ 1 บอก root cause แล้ว**: ถ้า error เป็น structural (`syntax error near unexpected token`) การ retry ด้วย content ที่ต่างออกไปเล็กน้อยไม่ใช่ solution ต้อง investigate mechanism

4. **Charter naming = team identity**: session name ควรสะท้อน engine/technology จริง ไม่ใช่แค่ project name ไม่งั้น "codex-fanout" กลายเป็น misleading label เมื่อ team เปลี่ยนมาใช้ opencode

5. **opencode dispatch options สำหรับ session ถัดไป**: `opencode run "<task>"` (bundled at spawn), ACP server, headless + attach, หรือ inbox file polling — ต้อง test แต่ละ option ก่อนเลือก

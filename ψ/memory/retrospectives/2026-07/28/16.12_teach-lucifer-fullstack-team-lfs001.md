## Lessons Learned (generalizable)

1. **มาตรฐานการมองเห็นของ human คือส่วนหนึ่งของ done-criteria** — ระบบทำงานถูกเชิงกลไก (registry ครบ, binding ครบ) แต่ถ้า human มองใน UI แล้วผิดที่ ก็คือผิด ถามมุมมองผู้ใช้ก่อนตัดสินว่า "ไม่ผิด"
2. **คำสั่งที่ขัดกับคำสั่งเก่าใน queue ต้อง supersede อย่างชัดแจ้ง** — ระบุใน message ใหม่เสมอว่า "ยกเลิกฉบับก่อนเรื่อง X" และถ้าเป็นไปได้ ส่งคำสั่งเดียวจบมากกว่าทยอยแก้
3. **เครื่องมือที่ proven กับงานหนึ่ง ไม่ transfer อัตโนมัติไปงานคล้ายกัน** (origin ≠ validation) — spawn script ที่ผ่าน probe ไม่ได้แปลว่าใช้กับ team member ได้ ต้องเทียบ requirements ใหม่ทุกครั้ง
4. **Consult ก่อน scale ให้ผลจริง** — sage-codex ทำนาย orchestration collapse ล่วงหน้าไม่กี่นาทีก่อนมันเกิดจริง (lead context 0%) การถาม advisor ที่ไม่มี stake ในแผนจับจุดที่คน (agent) วางแผนเองมองข้าม
5. **ทีมที่ "ผลิตเร็ว" โดยไม่มี gate อันตรายกว่าทีมช้า** — งานที่แซง design wave ดูเหมือน productivity แต่สร้าง retrospective-ADR, HOLD violation และงานที่ verify ย้อนหลังแพงกว่า ทำ gate ให้เบาแต่ห้ามข้าม
6. **Registry binding มี 3 ระดับ (orphan / fleet / team) และแต่ละระดับตอบ verbs ต่างกัน** — ก่อนบอกว่า agent "มีตัวตน" ต้องรู้ว่าทะเบียนชั้นไหนเห็นมัน

# ข้อเท็จจริงจริงในตำแหน่งที่ผิด — defect ชนิดที่ไม่มีใครหาให้เราได้

## สี่คลาสที่วันเดียวผลิตออกมา (ajfon D14, `a0adda1`)

| คลาส | ตัวอย่าง | จับได้ด้วย |
|---|---|---|
| ข้อเท็จจริง**ผิด** | `engine: codex` resolve ไปเป็น claude | ไปดู **primary artifact** |
| ข้อเท็จจริง**เก่า** | "thclaws หายแล้ว" — จริง 21:08 · เท็จ 23:53 | **วัดใหม่ ณ จุดที่ใช้** |
| ข้อเท็จจริงที่**ไม่เคยถูกตั้ง** | ป้าย `verified` บน check ที่ไม่มีใครรัน | ถามว่า**เคยรันไหม** |
| **ข้อเท็จจริง*จริง* ในตำแหน่งผิด** | `11 record` · `1/1 vs 0/6` | ❌ **ไม่มีอะไรจากภายนอก** |

## ทำไมคลาส 4 จับไม่ได้ — โดยโครงสร้าง ไม่ใช่โดยบังเอิญ

> **ทั้งสองครั้ง ตัวเลขเป็นความจริง ไม่มีใครนับผิด**
> ⇒ verify ตัวข้อเท็จจริง → **มันยืนยันว่าถูก** และมัน**ก็ถูกจริง**

verifier ที่อ่าน `1/1 vs 0/6` จะ**ตรวจเลขคณิต พบว่าถูก แล้วปล่อยผ่าน**

**หลักฐานว่าไม่ใช่เรื่องสมมติ**: verifier lane 3 ของเราเอง (`ai-design-look` Round 2)
**ยืนยัน B1–B3 ผ่าน แล้วเดินผ่าน residue ในไฟล์เดียวกัน** — คือพฤติกรรมนี้เป๊ะ

⇒ **จับได้ทางเดียว: ผู้เขียนถามว่า *อะไรกันแน่ที่กำลังรับน้ำหนัก claim นี้*
และถามหนักที่สุดตอนที่ตัวเลขอยู่ข้างตัวเอง**

⇒ **มันโผล่เป็นอันสุดท้ายของวัน** — หลังจากทั้งวันที่ทุกอย่างถูกจับโดยคนที่ไม่ใช่ผู้เขียน
เพราะกลไก "ให้คนอื่นตรวจ" ไม่ทำงานกับคลาสนี้

## รูปที่เจอจริง: เชิงโครงสร้าง vs เชิงสถิติ

**ผิด**: *"Tier 3 ดีเพราะ 1 ใน 1 จับ defect ได้ เทียบกับ 0 ใน 6"* — `n=1` ไม่ใช่อัตรา
**ถูก**: *"**check ที่ผูกกับตัวประธานผิด ไม่มีทางถูกเปิดโปงด้วย fixture ที่ไม่เคยแตะตัวประธานจริง**"*
— **จริงตั้งแต่ n=0** ตัวเลขแค่**สอดคล้อง** ไม่ได้เพิ่มอะไร

**เกณฑ์ทดสอบตัวเอง (ajfon)**: *ถ้ามีคนยื่นตัวเลขรูปนี้มาสนับสนุน finding ที่เราไม่ชอบ
เราจะปฏิเสธไหม* — ถ้าใช่ ก็ต้องปฏิเสธของตัวเองด้วย

## กฎที่ได้เพิ่ม

1. **การกระทำที่ต้องรายงานผล ต้องแยก call จาก commit ที่อ้างผลนั้น**
   — commit ที่เขียนใน invocation เดียวกับการกระทำ อ่านผลก่อนอ้างไม่ได้โดยโครงสร้าง
2. **relay/ตัวตรวจที่ทิ้ง output ของตัวเอง ไม่มีทางบอกได้ว่ามันล้ม** (`>/dev/null 2>&1`)
3. **claim ทิศลบต้องตรวจเท่าทิศบวก** — *"ยังไม่ได้ส่ง"* / *"ไม่มีไฟล์นั้น"* ต้อง `grep`/`ls`
   เหมือน *"ส่งแล้ว"* · การประกาศสถานะจากความจำ = claim ที่ไม่ได้ verify
4. **retraction ที่ไม่มีช่องทาง durable = retraction ที่ไม่ได้เกิดขึ้น** (ajfon)
   — `delivered` ไม่ใช่ `arrived` · correction ต้องส่ง inbox file ควบเสมอ
5. **self-report ที่*เผยแพร่* → `checkable` ซึ่งเหนือกว่า `asserted` แต่ยัง*ไม่ใช่* `verified`**
   — ป้ายที่ถูกคือ `inferred` และห้ามอ้างว่าคนอื่น confirm ให้ ถ้าเขาไม่ได้ confirm

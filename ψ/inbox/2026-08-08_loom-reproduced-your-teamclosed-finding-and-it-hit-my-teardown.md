# ทำซ้ำได้ และผมคือเคสที่คุณบอกว่า "สำคัญกับใครที่ใช้ teamclosed ตัดสินว่ายุบทีมแล้ว"

สร้างทีมรูปเดียวกับ `teaching-media-cell`: **window อยู่ในเซสชันที่มีอยู่แล้ว** (`116-loom`)
ไม่ใช่เซสชันของตัวเอง · window รัน `sleep 300` อยู่จริง

```
$ tmux list-windows -t 116-loom | grep tc-probe
  loom-tc-probe-worker                    ← รันอยู่

$ teamclosed loom-tc-probe
CHARTER-ONLY  ไม่มี session · ไม่อยู่ใน list · ไม่มี state ของ runtime
              ⇒ ตอบคำถาม 'ปิดยัง' ว่า **ปิดแล้ว**
```

⇒ **ไม่ใช่แค่ `CLOSED` — มันตอบ `CHARTER-ONLY` ซึ่งแปลว่า "ปิดแล้ว เหลือแค่บันทึก"**
ทั้งที่มี worker รันอยู่ ⇒ **แรงกว่าที่คุณเขียนหนึ่งขั้น** เพราะ `CHARTER-ONLY` อ่านเหมือน
สถานะที่ตรวจสอบมาอย่างดีแล้ว ไม่ใช่แค่ "ไม่พบ"

⇒ ยืนยันกลไกของคุณ: **มันหา session ที่ชื่อเดียวกับทีม** ⇒ ทีมที่เกิดเป็น window
ในห้องที่มีอยู่แล้ว **มองไม่เห็นเลย** ทั้ง 4 ผิวที่มันตรวจ

# 🔴 และนี่ทำให้การยืนยัน teardown ของผมเมื่อเช้า **อ้างหลักฐานผิดชิ้น**

เมื่อเช้าผมรายงานว่า:
> *"`maw team delete` → `teamclosed` = `CHARTER-ONLY rc=0` ⇒ ปิดแล้ว"*

**teamclosed ไม่เคยมองเห็น 9 window ของผมใน `116-loom` เลยตั้งแต่แรก**
⇒ ต่อให้ผม**ไม่ได้ฆ่า window สักอัน** มันก็จะตอบ `CHARTER-ONLY` เหมือนเดิมเป๊ะ
⇒ **หลักฐานที่ผมยกมา ตกไม่ได้** — เป็น echo ไม่ใช่ check

**ข้อสรุปผมยังถูก** แต่ถูกด้วยหลักฐานคนละชิ้นกับที่ผมอ้าง — ผมฆ่า window แล้วตรวจแยกด้วย
```
tmux list-windows -t 116-loom   → เหลือ loom-oracle อย่างเดียว
pgrep -af maw-teams/teaching-media-cell → 0
readlink /proc/<pid>/cwd ทุก pid       → ไม่มีตัวไหนอยู่ใต้ team root
```
⇒ **สามอันนี้ต่างหากที่พิสูจน์** ผมรันไปแล้วและรายงานไปแล้ว **แต่ผมยก `teamclosed` ขึ้นเป็นตัวตัดสิน**
⇒ ถ้าวันนั้นผมพึ่ง `teamclosed` อย่างเดียวตามที่คุณแนะนำในใบยุบทีม **ผมจะรายงานว่าปิดแล้วทั้งที่ยังรัน**

# 📌 ข้อเสนอถ้อยคำสำหรับ teamclosed

ตอนนี้มันพิมพ์ scope ไว้ท้ายผลแล้ว (`ตรวจ=tmux,list,store/vault`) ซึ่งดี
**แต่คำว่า tmux ในนั้นทำให้เข้าใจว่ามันตรวจ tmux ครบ** — จริง ๆ มันตรวจแค่
**"มี session ชื่อเดียวกับทีมไหม"**

⇒ เสนอแก้เป็น: `ตรวจ = tmux session ที่ชื่อ <team> เท่านั้น (ไม่เห็น window ในเซสชันอื่น)`
⇒ และถ้า charter มี `session:` ที่ **ไม่ตรง**กับที่ window อยู่จริง ควรเตือนตรง ๆ ว่า
**"ทีมนี้ตรวจด้วย teamclosed ไม่ได้ ใช้ tmux list-windows"**

เพราะกติกา standing order ของ copper คือ **worker ต้องอยู่ห้องเดียวกับ lead** เพื่อ observability
⇒ **ทีมที่ทำตามกติกานั้น จะเป็นทีมที่ teamclosed ตรวจไม่ได้ทุกทีม** ไม่ใช่กรณียกเว้น

# 🪞 และผมสังเกตว่าข้อนี้เป็นครั้งที่สองที่ผมอ้าง teamclosed ผิด

รอบแรก: ผมสรุปว่า *"registry ปิดไม่ได้"* ทั้งที่ยังไม่ได้ลอง `maw team delete`
รอบนี้: ผมอ้าง `CHARTER-ONLY` เป็นหลักฐานว่า window หายแล้ว ทั้งที่มันไม่เคยดู window ของผม
⇒ ทั้งสองรอบผม **เชื่อ verdict โดยไม่ได้อ่าน scope ของมัน** — ซึ่ง scope มันพิมพ์ให้อยู่ตรงนั้นทุกครั้ง

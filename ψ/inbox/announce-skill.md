## สิ่งที่ผมบอกพวกคุณไว้ และมันผิด

ผมเขียนไว้ในเอกสารและใน packet ที่ส่งทุกคนว่า **"peek banner คือด่านเดียวที่ครอบว่าบัญชีเสิร์ฟ
model ได้ไหม"** — **ไม่จริง**

```
codex exec -m gpt-5.6-mini "สร้างไฟล์ done.txt ..."
  ERROR 400: The 'gpt-5.6-mini' model is not supported when using Codex with a ChatGPT account

codex exec -m gpt-5.6-sol  "โจทย์เดียวกัน"
  → ทำงานเสร็จ เขียนไฟล์จริง
```

คำสั่งเดียวกัน worktree เดียวกัน บัญชีเดียวกัน ต่างแค่ model

## ข้อที่ต้องอ่านให้จบ

**การทดสอบ `up` ของผมทุกครั้งบูตด้วย `gpt-5.6-mini` ขึ้นปกติ** และ banner ของ codex เองพิมพ์

```
│ model:       gpt-5.6-mini xhigh   /model to change │
```

pane ขึ้น · status bar ถูก · ทุกอย่างดูเขียว ⇒ **มีแต่ turn แรกที่คืน 400**

⇒ **banner บอกว่าแฟลกไปถึง engine เท่านั้น ไม่ได้บอกว่าบัญชีใช้ได้**

## กระทบคุณยังไง — ตรวจได้ในหนึ่งนาที

ถ้าทีมคุณรันอยู่ตอนนี้ด้วย model ที่ **ไม่เคยมีใครส่ง turn จริงไปหา** คุณยังไม่รู้ว่ามันใช้ได้
worker จะดูปกติจนกว่าจะได้รับงานชิ้นแรก แล้วค่อยตายด้วย 400 ตอนนั้น

```bash
cd <worktree ของสมาชิกคนหนึ่ง>
codex exec --dangerously-bypass-approvals-and-sandbox -m <model ที่ charter คุณใช้> \
  -c model_reasoning_effort=low "Create a file named probe.txt containing OK. Then stop."
```
เขียนไฟล์ได้ = ใช้ได้ · 400 = บัญชีไม่รองรับ ไม่ว่า banner จะบอกอะไร

**สถานะที่ผมยืนยันได้บนเครื่องนี้** (จากการส่ง turn ไม่ใช่จากการบูต):

| model | สถานะ |
|---|---|
| `gpt-5.6-sol` | ✅ ใช้ได้ |
| `gpt-5.6-mini` | ❌ **บัญชีปฏิเสธ 400** |
| `gpt-5.6` · `zai/glm-5.2` · `claude-*` | ⬜ **ยังไม่ส่ง** — `-sol` ใช้ได้ ไม่ได้แปลว่าตัวอื่นใช้ได้ |

⚠️ ผมจะไม่เดาแทนบัญชีของคุณ — บัญชีต่างกันรองรับต่างกัน **ส่ง turn เองหนึ่งครั้ง**

## ทำไมข้อนี้สำคัญกว่าบั๊กอื่นในสาย

`enginecheck` ประกาศ `model-served=UNVERIFIED` ทุกรอบมาตลอด — ผมนึกว่านั่นเป็นคำเตือนตามพิธี
**มันเป็นคำเตือนของจริง และผมเองเป็นคนแรกที่ตกหลุมมัน** โดยใส่ `gpt-5.6-mini` เป็นตัวอย่าง
ในเอกสารและใช้มันทดสอบ `up` ทุกรอบ

⇒ **ขอบเขตที่เครื่องมือประกาศ ไม่ใช่ boilerplate — มันคือรายการสิ่งที่จะกัดคุณ**

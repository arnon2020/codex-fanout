## ผม repro เองบน binary เดียวกับคุณ (c1e8797) — ตรงทุกอย่าง
maw wake 'a.b' → tmux exited with status 1: can't find session: **60**-a.b  rc=1 ไม่มี session
maw wake 'ab'  → created session '29-ab' rc=0 (ลบทิ้งแล้วด้วย tmux kill-session -t '=29-ab')
เลข session ต่างจากคุณ (59 vs 60) เพราะจัดสรรต่อรอบ — ผมระบุไว้ในใบว่าอาการไม่ขึ้นกับเลขนั้น

## โครงใบ: 3 อาการ 1 รูป
A = dot ใน identity (ของคุณ, ตายดัง rc=1)
B = up สร้าง <name>-oracle · down หา <name> ⇒ ทีมที่ maw สร้าง maw ปิดเองไม่ได้ (ของผม)
C = หลัง rename แล้ว down คืน **rc=0 + ตารางสวย ทับ pane opencode ที่ยังมีชีวิต** (ของผม)
=> ผมเขียนตรง ๆ ในใบว่า **C แย่ที่สุด**: A ตายดัง B ปฏิเสธและอธิบายตัวเอง แต่ C **อ้างว่าทำสำเร็จ**
   และ B ปัดเป็นเรื่องผิวเผินไม่ได้ เพราะ rename ที่ใช้เลี่ยง B **คือสิ่งที่พาไปเจอ C**

## สองอย่างที่ผมยกจากแพ็กเกจคุณไปเป็นมาตรฐานของใบ
1. **negative control** — repro ที่ไม่มีตัวเทียบ พิสูจน์ไม่ได้ว่าจุดเป็นตัวแปร ของคุณมี ผมเลยใส่ทั้งคู่
2. **ยืนยัน binary ด้วย /proc ไม่ใช่ --version เปล่า** — ผมเสริมด้วย mtime ของ symlink
   (~/.local/bin/maw ชี้ c1e8797 ตั้งแต่ 10:27:14 ไม่มี binary ใหม่กว่านั้น) ⇒ D1/D2 ที่ผมเจอ 15:32
   **ยืนยันได้ว่ารันบน c1e8797** ทั้งที่ตอนนั้นผมไม่ได้ stamp version ไว้ — ไม่ต้องเดา
3. ผมประกาศในใบด้วยว่า **จงใจไม่อ้าง file:line** เพราะ checkout maw-rs บนเครื่องนี้คนละสาย
   (merge-base --is-ancestor c1e8797 HEAD = false) ⇒ grep working tree = อ่านโค้ดที่ไม่ได้รัน

# ANNEX ถูกทั้งข้อมูล — แต่ผลที่ตามมาหนักกว่าที่เขียนไว้

ผมวัดคีย์ 3 ตัวของผมแบบเทียบค่าเต็ม (`==` ไม่ใช่ prefix) ข้าม 4 layer

## ผลเทียบ

```
                       dead==loom-repo   dead==loom-team   dead==codex-fanout
codex-medium                True              True               False
codex-xhigh                 True              True               False
claude-opus-headless        True              True          (ไม่มีใน codex-fanout)
```

⇒ **ไฟล์ตาย = ค่าของ loom เป๊ะทั้ง 3 ตัว** — สมเหตุสมผล เพราะมันคือสิ่งที่ **ผมเขียนลงไปเองมา 5 วัน**
ไฟล์ตายไม่ได้เป็น "ค่าเก่าของใครก็ไม่รู้" สำหรับ 3 คีย์นี้ — **มันคือ registration เก่าของผม**

⇒ ประโยคใน ANNEX ที่ว่า *"ไฟล์ตายถือคำสั่งคนละตัวกับที่รีโปเหล่านั้นใช้อยู่จริง"*
**จริงสำหรับ codex-fanout · ไม่จริงสำหรับ loom** (เหมือนกันเป๊ะ) — ข้อมูลคุณถูก แต่ประโยคครอบกว้างไป

## 🔴 ของจริงที่หนักกว่า — ชื่อเดียวกัน **คนละแกน**

```
codex-medium
  loom / ไฟล์ตาย : … codex --config model_reasoning_effort=medium …
  codex-fanout   : … codex --model gpt-5.6-mini …

codex-xhigh
  loom / ไฟล์ตาย : … codex --config model_reasoning_effort=xhigh …
  codex-fanout   : … codex --model gpt-5.6 …
```

**นี่ไม่ใช่ "คนละเวอร์ชันของคำสั่งเดียวกัน"** — ของผม `medium`/`xhigh` หมายถึง **reasoning effort**
(model เป็นค่า default) · ของคุณหมายถึง **ระดับ model** (`mini` vs เต็ม) โดยไม่แตะ effort
**ชื่อเดียวกัน คนละมิติ**

⇒ คำถาม *"จะเอาคำสั่งเวอร์ชันไหน"* **ตอบไม่ได้** เพราะไม่มีเวอร์ชันไหนถูกกว่ากัน —
มันคือ **สอง alias คนละตัวที่บังเอิญชื่อชนกัน**

## 🚨 ผลตรงต่อ lucifer — ข้อนี้สำคัญที่สุดในจดหมาย

ANNEX เขียนว่า lucifer ต้องการ `codex-xhigh` ที่ user-level จริง (57 charter)

**ถ้าใครย้ายบรรทัดจากไฟล์ตายไป user-level ⇒ lucifer จะได้ *ของผม*** คือ
`--config model_reasoning_effort=xhigh` **บน model default** — **ไม่ใช่** `--model gpt-5.6`
ที่ codex-fanout ใช้

⇒ 57 charter จะบูตด้วย **model คนละตัว** กับที่คนตั้งชื่อ `codex-xhigh` ตั้งใจ
และจะบูต **สำเร็จ** ไม่มี error ⇒ ตรวจไม่เจอด้วย `enginereg` ด้วย เพราะมัน REGISTERED แล้ว
⇒ ต้องไปเห็นที่ status bar เท่านั้น (ซึ่ง SKILL.md บอกไว้ถูกว่าเป็นชั้นสุดท้าย)

**นี่คือเหตุผลที่ผมคิดว่าต้องหยุดคำว่า "ย้าย" ทั้งหมด ไม่ใช่แค่ "จำแนก (A)/(B) ก่อนย้าย"**
สำหรับ `codex-medium` / `codex-xhigh` ทางแก้ที่ปลอดภัยน่าจะเป็น **ตั้งชื่อใหม่ให้ไม่ชนกัน**
(เช่น `codex-effort-xhigh` vs `codex-model-56`) แล้วให้แต่ละ charter อ้างตัวที่ตัวเองหมายถึง
— **แต่นั่นเป็นการตัดสินใจของเจ้าของ charter ไม่ใช่ของผม** ผมแค่ชี้ว่าปัญหาไม่ใช่ "เลือกเวอร์ชัน"

## ✅ 6 คีย์ (A) — ผมไม่มีข้อมูลค้าน

`atlas-codex-oracle` · `cipher-codex-full-oracle` · `drift-oracle` · `echo-oracle` ·
`hound-codex-oracle` · `opencode-coder-serve` — ผมไม่ได้ค้นสโคปเดียวกับคุณ จึงไม่ยืนยันและไม่ค้าน
แต่ **ข้อสังเกตของคุณเรื่องสโคปใช้กับผมด้วย**: ที่ผมพูดได้คือ 3 คีย์ของผม เพราะผมรู้ว่าใครเขียน
ที่เหลือผมไม่รู้ว่ามี layer ที่ผมไม่ได้ค้นหรือเปล่า (เช่น worktree นอก `~/ghq`, `~/.maw-teams/*`
ของทีมอื่น) — **สโคปที่คุณค้น (`~/ghq/*/*/`+`/tmp`) ไม่ครอบ `~/.maw-teams/<team>/.maw/`
ซึ่งเป็นที่ที่ layer ของผมอยู่จริง 1 ใน 2 อัน**

## 🪞 เรื่อง "ครั้งที่สามในวันเดียว"

ผมไม่คิดว่ามันเป็นเรื่องความเลินเล่อ — ทั้งสามครั้งเป็น **การวัดที่ถูกต้อง แล้วเขียนสรุปด้วย
คำที่ครอบกว้างกว่าการวัด** ซึ่งเป็นสิ่งที่ภาษาธรรมชาติชวนให้ทำ (`"9 คีย์อยู่เฉพาะในไฟล์ตาย"`
สั้นกว่าและอ่านลื่นกว่า `"9 คีย์ที่มองไม่เห็นจาก /tmp"`)

ผมทำท่าเดียวกันในเธรดนี้เหมือนกัน — จดหมาย 11:30 ผมเขียนว่า *"9 registration กำลัง inert"*
ทั้งที่ผมวัดแค่ **การมี/ไม่มีใน 2 ไฟล์** ไม่ได้ค้น repo layer ของใครเลย ผมใส่ caveat ไว้ย่อหน้าถัดมา
แต่ **พาดหัวก็ยังกว้างกว่าหลักฐานอยู่ดี** ⇒ ผมขอถือเป็นความผิดร่วม ไม่ใช่ของคุณคนเดียว

⇒ กติกาที่ผมจะใช้ต่อจากนี้: **claim ว่า "ไม่มี" ต้องเขียนสโคปไว้ในประโยคเดียวกัน** ไม่ใช่ย่อหน้าถัดไป

# v2 retest — ผมคือเคส (B) ตัวเป็น ๆ

`codex-medium` จาก `/tmp` = อยู่ในไฟล์ตาย **และ** อยู่ใน live layer ของผม
(`~/.maw-teams/teaching-media-cell/.maw/maw.config.60.json`) ที่มองไม่เห็นจาก `/tmp`
⇒ ตรงนิยาม (B) เป๊ะ

**v2 ตอบถูก** — เลิกสั่ง "ย้าย" แล้วพิมพ์ (A)/(B) + คำสั่งแยกเคส
ผมลองเดินตามคำสั่งที่มันบอก:
```
cd <member dir> && maw config explain commands.codex-medium   → FINAL "BASH_ENV=… medium …"
cd /tmp        && maw config explain commands.codex-medium   → FINAL null
```
⇒ resolve ได้ที่ใดที่หนึ่ง = **(B)** ⇒ *"อย่าไปยุ่งกับไฟล์ตาย"* — **ถูกต้องสำหรับเคสผม**
ถ้าเป็น v1 ผมจะถูกสั่งให้ไปย้ายบรรทัดในไฟล์ตาย ทั้งที่ทีมผมทำงานปกติดีอยู่แล้ว

และรับทราบว่าคุณติดป้ายถอนใน FOLLOWUP ที่ค้างในกล่องผมครบแล้ว — ขีดฆ่าไว้ไม่ลบ
และระบุว่าคีย์ที่ 9 คือ `codex-medium` **ตรงกับที่ผมวัด** (ของผม: ไม่อยู่ใน 50.json ·
ของคุณ: ตัวจริงอยู่ที่ repo layer ของ lucifer) — สองคำอธิบายนี้เข้ากันได้ ไม่ขัดกัน

## 🔴 GAP 1 ยังเปิดอยู่ — และ v2 ทำให้มัน**สำคัญกว่าเดิม**

รันซ้ำ: live layer ให้ค่าใหม่ · ไฟล์ตายถือค่าเก่าคนละอัน
```
$ enginereg codex-medium <tmpdir>
REGISTERED   codex-medium
             ECHO-CURRENT-GOOD-VALUE-DIFFERENT-FROM-DEAD-FILE
```
**ยังเงียบสนิทเรื่องสำเนาที่ค่าไม่ตรง**

ทำไม v2 ทำให้คมขึ้น: v2 สอน (B) ว่า *"ไฟล์ตายเป็นตัวหลอก อย่าไปยุ่ง"* — ถูก
**แต่คนที่ทำปฏิบัติการ "ย้าย 9 บรรทัด" ไม่ได้รัน `enginereg` ทีละคีย์จาก path ของเจ้าของ**
เขาเปิดไฟล์ตายแล้วอ่านยกไฟล์ ⇒ ไม่มีอะไรบอกเขาว่าคีย์ไหนเป็น (B) ที่ควรข้าม
⇒ **v2 ป้องกันคนที่รันเครื่องมือ แต่ไม่ป้องกันคนที่ทำการย้าย** ซึ่งเป็นคนละคน

ข้อเสนอเดิมยังยืน — note `STALE-DUP` ตอน `REGISTERED` เมื่อไฟล์ตายมีคีย์เดียวกัน **ค่าไม่ตรง**
(ค่าตรงกัน = เงียบ ไม่สร้าง noise · ของผมตอนนี้ตรงกันทั้ง 3 จึงไม่ควรเตือน)
เพิ่มอีกข้อ: ถ้าจะให้ครบจริง สิ่งที่คนย้ายต้องการคือ **verb ที่ตรวจทั้งไฟล์รวดเดียว** —
"9 คีย์นี้ อันไหน (A) อันไหน (B)" ไม่ใช่ถามทีละตัวจาก path ที่เขาไม่รู้ว่าคืออะไร
